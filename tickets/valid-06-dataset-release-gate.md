Independent decoded-pixel census at base `14e792f`: the original 1,000 samples contain 51 duplicate-image groups, including `font-verdana-v02`, `v05`, and `v17` with identical pixels and different weight/modifier labels. Both generations contain single-line `font-oswald-v05` and `v17`. The 639-image set has no exact decoded-pixel duplicates but lacks saved font assets and line geometry.

## Plan

1. Build a read-only CLI and API that checks every image and emits a complete JSON report with failing exit status.
2. Require shared frozen catalog, prompt, pangram, recipes, skipped-candidate census, PNG hashes, font file hashes/internal identities, actual browser glyph faces, native weight/style, and at least two in-bounds text lines matching the CSS labels.
3. Independently decode every PNG, reject blank/clipped images and duplicate pixels, verify image dimensions, and publish distributions plus width/tracking shortcut baselines.
4. Require the gate before live clients/calls and show it on the benchmark page. Keep offline fixtures/mock operation available.
5. Preserve old data and paid checkpoints; write a new dataset and freeze its successful report.

## Decisions and durable findings

- Evidence is generated by a tested Chromium/font-binary renderer and bound to image/font SHA256 hashes. The gate checks consistency and artifact integrity; it is not cryptographic attestation against a malicious dataset author.
- Geometry verifies line boxes and spacing; the independent pixel pass checks visible ink, clipping at image boundaries, corruption, and duplicate inputs. Representative visual review remains necessary for perceptual problems that geometry cannot prove absent.
- Empty manifests and malformed nested evidence fail with actionable reports. Missing evidence never silently passes as legacy-compatible live data.
- Exact source font bytes are frozen locally for reproducible rendering. Publishing or redistributing provider fonts is separate from this local audit.
